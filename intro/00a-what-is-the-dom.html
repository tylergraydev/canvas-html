What is the DOM?

When the browser reads your HTML, it doesn't keep the text — it builds a tree of live objects from it, one object per tag. That tree is the DOM (Document Object Model). It's what you see on screen, what your JavaScript pokes at, and what a screen reader walks. Here's the same tiny page shown three ways: the HTML you write, what it renders to, and the tree the browser actually builds.

It's a tree of nodes

Every tag becomes a node; nesting becomes parent/child.

An <article> with a heading and a button inside it becomes an article node with a h2 child and a button child. Text is a node too. The browser keeps this structure in memory and paints the screen from it.

It's live, not a photo

The DOM isn't a snapshot — it's the running state of the page. Click the button below and its node's text changes; the screen updates because the DOM changed. Inputs hold focus, text is selectable, and assistive tech reads the roles and labels off these very nodes.

Keep this in mind for the next primer: a <canvas> is the opposite — no tree, no nodes, just a flat grid of pixels.
