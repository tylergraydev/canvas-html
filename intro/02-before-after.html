Before vs After

The exact same account card, rendered two ways into a canvas. On the left, the old way: the UI is hand-drawn with fillRect/fillText (or rasterized to an image) — a frozen, dead picture. On the right, the same card painted with drawElementImage() — still a real, live DOM node that floats and glows with plain CSS @keyframes animations (no JavaScript loop). Interact with both and watch only one answer.

Try it: click the input in each card and type, click the button, then press Tab to move focus. The left card is just pixels — nothing happens. The right card is alive.

What's actually different

          

            Both canvases end up holding pixels — that part is identical. The difference is
            where the pixels come from. The left card is drawn once with imperative canvas
            calls, so it can never update or respond; reproducing a real form that way means
            re-implementing focus, carets, selection and accessibility by hand (almost nobody does).
            The right card is a normal <article> with an <input>
            and a <button> living inside <canvas layoutsubtree>; the
            browser keeps laying it out and routing its events, and drawElementImage() just
            stamps its current appearance into the bitmap every repaint.
          

          

            Even the motion is plain CSS. The card's glow and the breathing badge are
            @keyframes animations on the element; because they animate painted
            properties, the browser repaints the element each compositor frame, which re-fires
            onpaint — so the script runs zero animation math and just
            re-stamps the latest frame (watch the live fps in the canvas badge). Animating the frozen
            left card would instead mean a hand-written requestAnimationFrame loop that
            redraws every primitive by hand.
